# PART B — the `PAGE LAYOUT` trees in `structure.md`

## The convention, read off the tree you wrote for main.html

1. **One `- [ ] **PAGE LAYOUT**` node per page**, placed *after* that page's
   `*backlog*` block and before its prose notes.
2. **Reading order, top of the page down.** The tree is the page, not the
   feature list.
3. **Status glyph on every node**: `✅` built · `◑` partial · `[ ]` not built.
   A parent is `◑` when any child is.
4. **Node = `glyph **Name** — gloss`**. `{token}` for interpolated text.
   Table rows written as pipe columns, as you did for the ME/OE panels.
5. **Four levels, no more**: surface → region → component → variant/state.
6. **The division of labour**: the backlog above says *what is wrong and what is
   next*; the tree says *what is on the page and whether it exists*. **When a
   backlog item lands, it becomes a node in the tree and leaves the backlog.**
   That is the rule that keeps the two from drifting.
